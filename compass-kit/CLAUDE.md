# Project guide for Claude

This is a Compose Multiplatform app (Android + iOS) generated by Compass from the cmpose.dev template.

## Map

- `androidApp/`: Android entry point (Activity, `applicationId`)
- `iosApp/`: Xcode project that hosts the shared framework
- `shared/`: app shell, navigation graph, `di/initKoin.kt` (every Koin module is registered here)
- `core/*`: shared infrastructure (network, theme, persistence, database (Room), purchases, ads), only if present
- `feature/<name>/{contract,domain,data,presentation}`: one folder per feature, four layers
- `feature/monetization/{contract,presentation}`: paywall and ads demo screens, only if present (two layers)
- `feature/notes/{contract,presentation}`: blank's Room demo, only if present (two layers)
- `build-logic/`: Gradle convention plugins. Do not change their wiring.
- `design/`: the exported design, fonts, icons and sounds Compass prepared (read-only input)

## Definition of done

A change is finished only when every gate below passes in the current session. Run them with
the exact commands shown; `./gradlew build` is not used because it links release iOS frameworks
and runs out of memory.

<!-- compass:gates -->

The test gate counts the tests it runs on the iOS simulator, and zero tests is red: write unit
tests as you go (see `cmp-testing`). Host-only tests such as `KoinGraphTest` do not count.

The app also needs `.maestro/walkthrough.yaml` (see `cmp-maestro`); Compass records the demo
video from it.

## Which skill when

- Any Kotlin change: `cmp-code-rules`
- New screen, feature module, repository or data source: `cmp-feature`
- UI from files under `design/` or a mockup: `cmp-design-to-code`
- Maestro flow or testTags: `cmp-maestro`
- Unit tests: `cmp-testing`
- detekt findings: `cmp-detekt` (only when detekt is set up)
- Build failure, or before saying you are done: `cmp-verify`
- The owner asks for a commit: `cmp-commit` (follow its steps even if it is not auto-loaded)

## Rules that break the app most often

1. `@KoinViewModel` is imported from `org.koin.android.annotation`, never `org.koin.core.annotation`.
2. No `java.*`, `android.*`, `String.format` or `System.*` in `commonMain`; the iOS compile fails.
3. DTOs and database entities stay in `data`; `domain` and `presentation` never see them.
4. No `@Suppress`, baseline files or disabled rules to make a gate pass.
5. Do not touch the Gradle wrapper, the Kotlin/AGP versions or the `build-logic` plugin wiring.
6. Every module with `composeResources` (fonts, strings, sounds, drawables) needs
   `androidResources.enable = true` in its Android block:
   `kotlin { extensions.configure<KotlinMultiplatformAndroidLibraryExtension> { androidResources.enable = true } }`
   (full example in `cmp-feature`, `references/screen.md`). Without it the Android APK ships
   without those files while every gate stays green.
7. Every name in the code is English: modules, packages, classes, files, string keys — whatever
   language the request or the UI is in.
8. Database (only if `core/room` exists): add a table to the existing `AppDatabase`, never a second one:
   entity, DAO, the `entities` list and a `@Single` DAO provider. Commit `core/room/schemas/`;
   changing a table means bumping `version` and adding a migration.

## How to work

- Read the existing code before writing; the project's working code wins over any guide.
- Change only what the task needs. Do not create README or documentation files unless asked.
- In a headless run (`claude -p`) never ask questions: choose the reasonable option and list it
  under `Assumptions` in your final message.
- Never push. Commit only when the owner asks.
- Code, comments and commit messages are in English; talk to the owner in their language.
